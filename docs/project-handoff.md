## 1. 项目摘要

### 1.1 一句话定位

Career GenUI 是一个面向成人学习者与职业转型者的生成式界面产品概念与高保真交互原型。系统根据用户目标、任务结构和成长状态，在对话中动态调用消息卡、配置 Sheet 或临时全屏工作台；用户确认后的结果写回成长状态，并继续驱动下一项学习或职业任务。

### 1.2 项目要回答的问题

本项目重点验证三个产品判断：

1. 主模型能否判断一个任务是否值得进入 GenUI，而不是为所有回答生成界面。
2. 用户能否在动态界面中完成可操作、可校验、可确认的任务。
3. 确认结果能否形成状态补丁，并推动下一步学习、练习或职业转化。

### 1.3 当前阶段与边界

当前是作品集级高保真前端原型，不是已上线运营的正式产品。

- 已完成：市场判断、产品定位、信息架构、交互机制、演示故事线、前端原型、运行策略、技术架构、市场调研和自动化静态校验。
- 未连接：真实大模型、文件解析服务、语音服务、用户账户、服务端数据库、埋点平台和真实推荐系统。
- 数据口径：界面中的案例、识别结果和成长状态均为受控演示数据。
- 收益口径：用户收益、产品收益和商业收益均为待验证假设，不代表真实线上结果。

## 2. 用户、问题与产品判断

### 2.1 首发核心用户

高意图、时间受限的成人学习者和职业转型者，典型情境包括：

- 已经确定考试或求职目标，但不知道当前最应该补什么。
- 有基础财务经历，但 CPA 会计知识结构、会计判断和表达证据不完整。
- 学习材料、练习记录、简历和求职任务分散在不同工具中。
- 每周可投入时间有限，需要系统持续判断“下一步最值得做什么”。

### 2.2 核心问题

传统工具通常只解决链路中的一个环节：

- 聊天工具可以回答问题，但答案不会自然进入练习、计划和职业材料。
- 学习工具可以刷题，但结果不一定转成岗位能力和项目证据。
- 求职工具可以修改简历，却不了解用户刚完成的学习、练习和项目过程。

Career GenUI 的产品判断是：真正的差异不在于增加更多入口，而在于把一次对话转成可执行任务，再把任务结果转成连续状态。

### 2.3 产品运行主链

```text
用户表达目标或任务
  → 主模型理解意图、上下文与可信来源
  → 判断文本是否足以完成任务
      ├─ 足够：继续自然语言回答
      └─ 不足：判断是否进入 GenUI
            → 生成 Artifact Plan
            → Schema 校验
            → 选择消息卡 / Sheet / 临时全屏
            → 用户操作与局部反馈
            → 工具或模型完成校验
            → 用户确认
            → 生成 State Patch
            → 主模型解释结果并发起下一步
```

## 5. 完整演示动线

### 5.1 推荐时长

- 面试标准版：8～10 分钟。
- 电梯版：3 分钟。
- 深度评审版：15 分钟。

标准版的顺序固定为：

```text
项目定位
  → 用户问题
  → 产品三特征
  → 十阶段故事线
  → 深讲一次确认写回
  → 运行策略
  → 技术架构
  → 市场与收益假设
  → 项目边界和下一步
```

### 5.2 开场话术

> 这是一个面向成人学习者和职业转型者的 Career GenUI 产品概念与高保真交互原型。它不是把考试、学习、简历和求职功能堆在一起，而是让 AI 根据用户当前目标和成长状态，动态生成最合适的任务界面，并把确认后的结果写回长期状态，继续安排下一步。

随后明确边界：

> 当前是用于验证产品方向、交互机制和技术可行性的作品集原型，不是已经上线运营的产品。因此项目中的用户收益和商业收益属于待验证假设。

### 5.3 第一段：问题与产品全貌

停留在“场景体验”首屏，说明：

1. 成人学习与职业转型的任务分散。
2. 传统 AI 擅长回答，但缺少操作、确认和长期状态。
3. Career GenUI 使用“对话触发、动态执行、状态接力”连接任务。

不要逐个介绍 21 项功能。只介绍四个阶段和统一机制。

### 5.4 第二段：手动演示故事线

现场讲解优先点击“逐步查看演示”，自动模式主要用于观众自行浏览。

交互边界：手动模式只呈现当前阶段的入口与任务卡，资料载入、打开工作台、选择、作答、校验和提交都由演示者触发；只有切换为自动体验后，系统才运行计时演示脚本。

示例用户：

- 正在备考 CPA 会计，并准备审计助理或财务分析岗位。
- 有基础财务经历。
- 每周可投入 3 小时。
- 不清楚能力缺口，也不会把学习结果转成职业证据。

十阶段路径：

```text
目标诊断 → 资料导入 → 概念建构 → 刻意练习 → 阶段检验
→ 资料沉淀 → 岗位匹配 → 案例判断 → 面试训练 → 证据写回
```

每一阶段都按四个问题讲解：

1. 为什么此时进入界面？
2. 用户要完成什么操作？
3. 哪个结果经过确认后写回？
4. 这个结果如何改变下一步？

现场重点只深讲四个节点：

- 目标诊断：形成岗位、时间和能力起点。
- 理解与练习：从材料结构转成可检验的掌握状态。
- 岗位与证据：把已掌握能力翻译成岗位要求和项目证据。
- 面试训练：把最低分项写回为新的练习任务。

### 5.5 第三段：深讲一次交互闭环

推荐打开“模拟项目深挖面”。

演示动作：

1. 进入连续问答。
2. 补充会计判断、底稿证据或个人贡献。
3. 查看结构化反馈。
4. 运行最终校验。
5. 点击“确认并写入成长档案”。
6. 返回对话，观察下一步推荐变化。

讲解重点：

> 用户在界面中的操作先进入任务草稿。系统可以反馈，但只有用户确认后才写入长期成长状态。写回结果随后影响练习计划、岗位匹配和面试建议。

### 5.6 第四段：运行策略

点击“运行策略”，重点展示：

- 主模型先判断文本是否足够。
- 只有存在有意义操作、稳定结构和状态价值时才进入 GenUI。
- 风险、来源和端侧空间不满足时，系统追问、降级或停止推导。

核心结论：

> GenUI 不是为了让对话看起来更丰富，而是在结构化操作能明显提高任务完成质量时才进入。

### 5.7 第五段：技术架构

点击“技术架构”，只讲三个原则：

1. 生成与执行分离：主模型负责理解和规划，运行时负责校验、渲染、工具和状态。
2. 草稿与正式状态分离：未经确认的操作不能直接修改长期状态。
3. 结果可恢复、可解释：Artifact 有明确生命周期、来源、版本和幂等策略。

### 5.8 第六段：市场与产品收益

最后点击“市场调研”，说明：

- 免费题库、公开内容和 AI 问答逐渐成为标准入口。
- 诊断层负责把免费使用连接到持续任务和付费权益。
- 高客单价依赖更深结果责任，但也会引入更高履约成本。
- Career GenUI 优先验证跨任务接力，而不是立即证明收入。

建议观察的产品指标：

| 指标 | 定义 | 当前状态 |
|---|---|---|
| 首次有效任务完成率 | 首次会话内完成一个可确认任务的用户占比 | 待验证 |
| 有效写回率 | 完成操作后确认写入长期状态的任务占比 | 待验证 |
| 下一步采纳率 | 用户在结果卡后继续推荐任务的比例 | 待验证 |
| 跨模块接力率 | 用户从学习任务继续到证据、岗位或面试任务的比例 | 待验证 |
| 状态纠错率 | 用户修改或撤回系统状态判断的比例 | 待验证 |

### 5.9 收尾话术

> 这个项目最终验证的不是 AI 能不能生成页面，而是对话能否识别一个值得界面化的任务，用户操作能否形成可确认结果，以及这个结果能否进入长期状态并推动下一步。下一阶段最重要的不是继续增加功能，而是用真实用户验证首次任务完成、确认写回和跨模块接力是否成立。

## 7. 核心交互与状态机制

### 7.1 三类显示形态

| 形态 | 适用任务 | 示例 |
|---|---|---|
| 消息卡 | 步骤少、可在会话中完成 | 结果摘要、下一题、推荐接力 |
| Bottom Sheet | 需要补充少量参数，但不应打断上下文 | 时间预算、过滤条件、任务调整 |
| 临时全屏工作台 | 连续操作、复杂比较或多步校验 | 诊断、概念图、模拟考试、案例研讨、面试训练 |

### 7.2 Artifact 生命周期

```text
Created → Draft → Validated → Committed → Relayed
                     ↓
              Cancelled / Restorable
```

- Created：创建初始结构。
- Draft：保存局部操作，不修改长期状态。
- Validated：完成字段、工具和风险校验。
- Committed：用户确认后原子写回。
- Relayed：主模型根据最新状态发起下一步。
- Restorable：中断后恢复任务位置和草稿。

### 7.3 写回原则

- 未经确认，不写长期状态。
- 只写入能解释下一步的有效字段。
- 用户可以撤销、纠正或重新执行。
- 高风险结论需要来源、版本和复核策略。
- 关闭全屏不等于提交。

### 7.4 关键前端状态

`demo/index.html` 内保留以下机制：

- `APP_STATE`
- `reducer`
- `dispatch`
- `localStorage`
- Artifact 草稿与提交
- Sheet 和全屏工作台
- 撤销、继续、重置和清空
- 故事线自动与手动模式
- 减少动态效果和键盘焦点样式

## 9. 本地运行与验证

### 9.1 启动

在仓库根目录执行：

```bash
python3 -m http.server 8000
```

访问：

- Demo：<http://localhost:8000/demo/>
- 市场报告：<http://localhost:8000/research/competitive-analysis.html>
- 嵌入版市场报告：<http://localhost:8000/research/competitive-analysis.html?embed=1>

### 9.2 静态校验

```bash
node scripts/validate-demo.mjs
```

当前基线：32 项全部通过。

### 9.3 人工回归清单

每次修改后至少验证：

- 场景体验、运行策略、技术架构、市场调研四个页签均可切换。
- 手机与报告保持约 45/55。
- 页面无文档级横向溢出。
- 报告正文和卡片文字在实际画幅中可读。
- 字号增大后卡片自动增高，不裁切文本。
- 四卡区域使用 2×2，不出现 3+1。
- 表格和密集图表使用内部滚动，不撑破报告区。
- 自动演示可暂停、恢复和完成。
- 手动演示不会自行跳转。
- Sheet 可关闭，Escape 后焦点返回触发按钮。
- 全屏任务未确认时不写长期状态。
- 确认写回后出现下一步接力。
- 撤销、继续、重置和清空仍可使用。
- 控制台无 warning、error 和 Promise 异常。

## 11. 修改约束

以下是明确的产品与交付约束。

### 11.1 不可随意删除

- 四阶段导航。
- 21 项可见功能入口。
- 十阶段故事线。
- 自动和手动两种演示模式。
- Sheet、全屏、状态恢复、撤销、清空和写回机制。
- 运行策略、技术架构和完整市场报告。

故事线只负责串联演示，不能用故事线替代产品能力。

### 11.2 对外脱敏

- 不出现原平台名称、原品牌标识和可识别业务项目名。
- 对外统一使用 Career GenUI、职路 AI 或通用 AI 标识。
- 不暴露个人简历、真实用户数据、真实公司内部材料或密钥。

### 11.3 视觉与排版

- 桌面保持手机 45%、报告 55% 的结构意图。
- 手机尽量占满可视高度。
- 报告正文优先保证可读，不通过缩小文字解决布局问题。
- 普通正文不应小于约 13px 的可视尺度。
- 卡片使用自适应高度，禁止依赖固定高度裁切文本。
- 四张同类卡片采用 2×2。
- 密集表格或图表使用内部横向浏览。
- 组件重排优先于字号缩小。

### 11.4 内容口径

- 场景体验以产品特征为主角，故事线是辅助。
- 市场报告第一篇和第二篇都要保留。
- 不把原型描述成真实线上服务。
- 不把目标指标描述成真实运营结果。
- 不声称模型自由生成任意前端代码。
- 技术表达应说明受控 Schema、组件注册和确定性执行。

## 13. 已知边界与风险

### 13.1 产品验证不足

目前没有真实用户行为数据。目标用户、任务频率、跨模块接力需求和付费方式仍需验证。

### 13.2 技术为受控模拟

当前状态机、工具结果和模型回复由前端受控数据驱动。真实落地需要：

- 模型路由与上下文服务。
- Artifact Schema 注册与版本管理。
- 工具权限和执行审计。
- 服务端状态与账户体系。
- 来源、检索与专业复核。

### 13.3 单文件维护成本

`demo/index.html` 便于公开展示和快速运行，但随着功能继续增长，可维护性会下降。正式产品应拆分：

- Design Tokens 与组件样式。
- Artifact Renderer。
- 运行时和状态机。
- 能力注册表。
- 场景数据与演示脚本。
- 自动化端到端测试。

### 13.4 报告密度较高

报告承担作品解释和产品设计证明，信息密度高于普通消费产品。继续优化时，应优先改进章节导航、重点摘要和渐进展开，而不是继续减小字号。

## 15. 常见问答

### 它与普通聊天机器人的区别是什么？

普通聊天主要交付答案，Career GenUI 交付可操作任务、经过确认的状态变化和下一步接力。

### 为什么一定需要 GenUI？

并非所有任务都需要。只有涉及多步操作、结构化修改、连续练习或正式写回时，界面才比文本更有效。

### 页面是否由 AI 实时自由生成？

当前是高保真原型。正式实现应采用受控 Schema、组件注册表和确定性 Renderer，不允许模型自由执行任意前端代码。

### 项目是否已经上线？

没有。当前是产品方向、交互机制和技术边界验证原型。

### 项目的产品经理价值体现在哪里？

核心价值不是页面数量，而是定义了目标用户、连续任务链、GenUI 准入条件、写回边界、模块状态接力、风险策略和验证指标。
