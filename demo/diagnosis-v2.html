一、重新定义用户体验阶段

原来的十个功能是能力清单，不是用户路径。新的阶段按用户要完成的任务组织。

1. 诊断定位明确目标、状态、能力与证据缺口本期详细落地
2. 目标规划把差距转成阶段目标与优先级
3. 能力训练围绕关键缺口进行学习与练习
4. 求职验证通过 JD、案例、面试检验能力
5. 证据沉淀将结果写回简历、作品集与画像

三、诊断运行策略

不是一次性问卷，而是“预填—卡片确认—证据读取—增量追问—输出行动”的动态周期。

环节用户操作系统策略产出
触发点击三个首页白条之一以入口文案作为初始意图，不重复询问诊断任务类型
预填确认卡片复用历史画像、简历和学习记录；只展示待确认字段目标/状态/岗位族
取证授权读取材料抽取项目、技能、成果、时间、证据强度，并标记来源职业证据池
追问回答 0—2 个问题仅当缺失字段会改变岗位结论或行动优先级时追问约束与偏好
诊断查看结果目标清晰度 20% + 能力匹配 35% + 证据充分度 30% + 约束适配 15%分项得分与可解释结论
闭环选择下一步最多给 3 个动作；完成后结果写回画像并重新诊断行动卡与画像更新

四、开发范围控制

把复杂愿景压缩成可演示、可验证、可逐步扩展的 MVP。

本期必须开发

首页三个入口、5 步卡片诊断、简历文本解析、基础岗位族、规则评分、诊断结果卡、三个行动建议、来源与置信度展示。

本期不开发

十个成长功能的完整交互、实时岗位库、复杂知识图谱编辑、长期学习计划、多人协作、语音面试、自动投递与全量 Agent 编排。

五、关键验收指标

首轮诊断完成率 ≥ 70%；用户主动输入字段 ≤ 5 个；平均完成时间 ≤ 3 分钟；结果中每条判断均有证据来源；下一步行动点击率 ≥ 40%；诊断后“方向更清晰”主观评分 ≥ 4/5。
